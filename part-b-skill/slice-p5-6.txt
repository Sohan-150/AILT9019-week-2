Topic idea list 
Starting points, not a menu. Pick one, adapt one, or propose something else. For each idea you 
shortlist, write one sentence naming the user group and single task, and one line naming the dataset 
(source + permission). The numbered examples below each give  a suggested user group, task, and 
an explicit “does not” (what the project will refuse to do). Difficulty bands are Easy / Medium / 
Challenging — about build and evaluation difficulty this semester, not how unusual the topic is. 
Bands are guidance only, not a required track.

How to choose (do this before Week 3) 
1. Pick 2–3 ideas that feel interesting, then write one sentence per idea naming the single user 
group and single task. 
2. For each, name the dataset in one line, source plus permission to use (public, licensed, or 
self-curated). If you cannot name it, the idea is not ready. 
3. Match the Easy / Medium / Challenging band to your team’s experience; a finished Easy 
project beats an unfinished Challenging one. 
4. Avoid the crowd: a third of the cohort building the same project helps nobody. 
Proposal Quick self-check 
☐  One user group + one task can be named in a single sentence. 
☐  Dataset source and permission can be named in one line. 
☐  The core workflow is small enough to run end to end this semester. 
☐  At least one clear “does not” (out-of-scope) boundary is written. 
☐  Background states the idea source: which topic-list idea(s) and how far they were adapted, an 
external idea, or an original idea. The proposal content does not include group names or personal 
information (names, UIDs, emails).
